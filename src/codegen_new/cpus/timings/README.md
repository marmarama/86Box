# CPU Microarchitectural Timing Specifications (`x86_spec/timings`)

This directory defines microarchitectural execution and cycle models for simulated CPUs.

By cleanly separating **architectural instruction semantics** ([`../arithmetic.yaml`](file:///home/marm/src/86Box/src/codegen_new/x86_spec/arithmetic.yaml)) from **hardware implementation timings** ([`pentium.yaml`](file:///home/marm/src/86Box/src/codegen_new/x86_spec/timings/pentium.yaml)), the specification remains clean, maintainable, and strictly follows the Single Responsibility Principle.

---

## 1. Architecture: The Layered Timing Model

```
   ┌─────────────────────────────────────────────────────────────┐
   │ Instruction Specification (*.yaml)                          │
   │ - Declares semantics: dst = dst + src                       │
   │ - Declares timing class: class: alu_reg | alu_rm | alu_rmw │
   │ - Data dependencies: AUTO-INFERRED (dst read+write, etc.)   │
   └──────────────────────────────┬──────────────────────────────┘
                                  │
                 ┌────────────────┴────────────────┐
                 ▼                                 ▼
   ┌───────────────────────────┐     ┌───────────────────────────┐
   │ timings/486.yaml          │     │ timings/pentium.yaml      │
   │ alu_reg:  1 cycle         │     │ alu_reg:  1 cycle, PAIR_UV│
   │ alu_rm:   2 cycles        │     │ alu_rm:   2 cycles, PAIR_UV│
   │ alu_rmw:  3 cycles        │     │ alu_rmw:  3 cycles, PAIR_U │
   └─────────────┬─────────────┘     └─────────────┬─────────────┘
                 │                                 │
                 ▼                                 ▼
     codegen_timing_486.c              codegen_timing_pentium.c
     (Autogenerated C tables)          (Autogenerated C tables)
```

## 2. Automatic Variant Specialization (reg / rm / rmw)

Instructions in `*.yaml` only need to specify their high-level family class:
```yaml
family: ADD
  class: alu
```

The metacompiler (`x86gen`) automatically specializes the class based on operand access patterns:
* If destination is GPR and source is GPR/Immediate $\rightarrow$ **`alu_reg`**
* If destination is GPR and source is Memory $\rightarrow$ **`alu_rm`**
* If destination is Memory $\rightarrow$ **`alu_rmw`** (Read-Modify-Write)

Similarly for `ADC` / `SBB`:
```yaml
family: ADC
  class: alu_carry  # Dispatches to alu_carry_reg / alu_carry_rm / alu_carry_rmw (forcing U-pipe on Pentium)
```

## 3. Benefits for 86Box

1. **Replaces ~15,000 lines of brittle C tables**:
   - `codegen_timing_common.c` (`opcode_deps[256]` register dependency bitmasks).
   - `codegen_timing_486.c` (`opcode_timings_486[256]` and `opcode_timings_486_mod3[256]`).
   - `codegen_timing_pentium.c` (`pair_timings[4][4]` and `opcode_timings_pentium[256]`).
   - `codegen_timing_p6.c`, `k5.c`, `k6.c`, `winchip.yaml`, etc.
2. **Eliminates Human Error in Dependency Tracking**:
   - Register dependencies (`SRCDEP_REG`, `DSTDEP_REG`, `SRCDEP_EAX`, `IMPL_ESP`, `MODRM`) are inferred directly from operand descriptors and typed expressions. A typo omitting an input dependency in an array cannot occur.
3. **Pluggable CPU Models**:
   - Adding a new microarchitecture (e.g. AMD K5, Cyrix 6x86, WinChip2) only requires authoring a single declarative profile file mapping abstract classes to hardware cycle counts.
